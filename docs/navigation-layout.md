# 功能导航布局说明

## 设计目标

主界面导航由底部横向菜单调整为左侧纵向工作区，解决功能入口随模块增加而拥挤、下拉层级不易发现，以及窗口较窄时入口折叠不稳定的问题。

## 信息架构

- **行情与交易**：股票自选、市场行情、K 线分析、基金自选和研究中心。这些入口承担日常看盘与研究流程，放在导航上半区。
- **智能助手**：AI 智能体独立成组，避免与行情工具混排，也为后续增加自动化能力保留空间。
- **系统**：设置和关于固定在侧栏底部，与业务操作分离。
- **窗口操作**：全屏、隐藏和退出位于系统入口之后，降低误触退出的概率。

原有菜单项的路由、权限检查和事件处理保持不变；本次调整只改变入口的组织方式和视觉层级。

## 响应式行为

- 默认侧栏宽度为 `232px`，展示图标、标题和分组名称。
- 用户可将侧栏收起到 `64px`，收起后保留图标入口及组件自带的悬浮提示。
- 宽度不超过 `760px` 时自动使用紧凑侧栏；不超过 `520px` 时隐藏品牌文字，优先保证内容区可用空间。
- 内容区独立滚动，侧栏始终可见，避免长页面将导航带离视口。

## 主题与可访问性

- 明暗主题分别定义侧栏背景、边框和内容区颜色，避免暗色模式仍出现浅色底板。
- 主导航使用 `aside`、`nav` 和 `aria-label` 描述其结构。
- 市场状态区域使用 `aria-live="polite"`，状态更新不会强制打断用户当前操作。

## 验收重点

1. 各业务入口仍能进入原有页面，股票分组和二级菜单仍可展开。
2. 收起、展开侧栏时内容区不应被遮挡或出现横向滚动条。
3. 设置、关于、全屏、隐藏和退出不再与高频业务入口混排。
4. 浅色与暗色主题下文字、边框和选中状态均应清晰可辨。
5. 在窄窗口中仍能通过图标访问全部功能。
