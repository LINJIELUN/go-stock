# 收盘后分析优先的产品范围

更新日期：2026-08-17

## 核心目标

软件不是实盘交易终端，也不用于高频策略调整。第一版核心链路调整为：

1. 交易日收盘后取得完整且可复核的 A 股数据；
2. 15:30 后筛选候选并运行 AI 分析；
3. 保存推荐完成时的价格、数据截止时间和预测快照；
4. 第七交易日收盘后使用有效收盘价复盘；
5. 持续评估方向命中、区间命中和概率校准。

## 数据优先级

### P0：阻塞推荐的数据

- 交易所交易日历；
- 股票/ETF身份、交易所、上市状态、ST/新股/退市整理标识；
- 日线开、高、低、收、成交量、成交额；
- 明确的前复权/后复权/不复权口径；
- 推荐基准价的行情时间；
- 第七交易日有效收盘价；
- 新闻、公告和财务数据的发布时间与抓取时间。

P0 数据缺失、日期不完整或收盘价复核不一致时，不生成正式推荐，也不完成复盘。

### P1：盘中自选辅助数据

- 最新价与涨跌幅；
- 量比、换手率；
- 成交量与成交额；
- 主力净流入（仅在供应商口径明确时显示）。

盘中自选第一版允许最多 5 分钟轮询、行情年龄 P95 最多 15 分钟，必须显示行情时间和来源。该指标是产品初始验收阈值，仍需实测；它不是“实时行情”承诺。

## 准确性的可执行定义

“保证准确”不能解释成市场数据永不出错。第一版将其拆成可验证要求：

- 测试窗口内交易日期覆盖率必须为 100%；
- 用第二个独立来源复核时，标准化到相同复权口径和价格精度后的收盘价不允许出现未解释差异；
- 每条数据保留来源、市场时间、抓取时间和复权方式；
- 修订数据必须生成修订记录，不能静默覆盖已经用于推荐的快照；
- 供应商异常时停止正式分析，而不是用零值或过期缓存继续运行。

这仍不能证明上游数据绝对正确，但能防止已知缺失、口径混淆和不可追溯数据进入预测。

## 架构影响

- 默认供应商准入策略改为 `end_of_day_analysis`；
- 盘中能力使用独立的 `intraday_watchlist` 策略，不再反向抬高核心数据采购成本；
- 主力净流入从默认强制准入项降为可选字段；
- 后续优先开发收盘数据核对、交易日历适配和分析任务调度，而不是 WebSocket 或秒级轮询。

## 当前双源实施状态

- TuShare Pro 适配器作为候选主源，提供不复权股票/ETF日线及有文档支持的沪深交易日历；尚未使用真实 Token 验收。
- 东方财富公开 K 线端点已封装为 `eastmoney-public-reference`，只用于技术交叉核对。其公开网页接口在本项目中没有已验证的 SLA 或再分发授权，因此不能通过“核对结果一致”自动升级成生产主源。
- 两个来源都只以不复权口径进入当前核对器；任何前/后复权需求必须另行验证复权因子和公司行为处理。
- 双源均非空仍不代表数据正确；必须同时满足交易日期覆盖、代码一致、日期范围、OHLC有效性和收盘价容忍差异。

双源验证服务已经完成编排：先读取指定交易所日历，再依次获取候选主源和独立复核源，并执行统一核对。只有核对结果完全通过时才释放主源日线给后续 AI 分析；出现数据源错误、代码/来源伪装、缺失日期或价格差异时，返回证据报告但不释放可分析数据。当前仍未配置真实 TuShare Token，因此该结论只表示编排逻辑通过本地测试，不表示真实供应商已经验收。
