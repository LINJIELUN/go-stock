# AI 推荐与实时自选产品决策

> 更新日期：2026-08-10。本文记录产品负责人已确认的业务口径，并把仍需验证的技术问题与产品决定分开。本文是实施前约束，不代表相关功能已经完成。

## 1. 已确认范围

### 1.1 市场范围

- 第一版只支持 **A 股**。
- 港股、美股不进入第一版实时自选、自动推荐、手动分析和七交易日复盘范围。
- 第一版包含上交所、深交所、北交所在市 A 股、交易所上市 ETF、ST 和 `*ST` 股票，也不因上市未满 60 个交易日而排除新股。
- 已退市证券默认不纳入可分析股票池；退市整理期股票是否纳入仍需单独确认。“包含 ST”不等同于应忽略其退市、流动性和涨跌停风险，这些风险必须进入推荐指数处罚项并显著提示。

### 1.2 实时自选

- 开市期间，自选股行情需要持续自动刷新。
- 自选股至少展示最新价、涨跌幅、量比、换手率、主力净流入等盘中指标。
- 页面必须展示行情时间、获取时间、数据源及过期或故障状态，不能把缓存值伪装成实时值。

“实时刷新”目前是产品目标，不是已经验证的 SLA。刷新间隔、端到端延迟、可用率、行情授权、限流和主备数据源尚未确认；完成数据源评估前，不对外承诺具体秒数。

### 1.3 AI 推荐结果

自动推荐和手动分析均需输出：

1. **七交易日上涨概率**：标注为“模型估计、非实际结果”；
2. **七交易日预计涨跌幅区间**；
3. **推荐购买指数**：0～100；
4. 推荐生成时间、基准价格、数据截止时间、模型与策略版本；
5. 推荐理由和风险提示。

“上涨概率”不得呈现为保证或已校准的客观概率。后续只有在积累足够的到期样本并完成概率校准评估后，才能补充展示历史校准结果。

### 1.4 自动推荐与手动搜索

- 每个 A 股交易日收盘后自动生成 **10～20 只**推荐股票。
- 保留手动搜索股票的入口。
- 搜索本身只负责定位股票；用户选择股票后触发单股 AI 分析，分析完成后展示与自动推荐相同的三项核心结果。
- 自动推荐和手动分析使用同一输出数据结构、版本记录和复盘规则，避免产生两套不可比较的数据。
- 模型调用失败、超时或数据不足时必须明确显示失败原因，不能用虚构数值补齐结果。

- 交易日自动推荐任务在 **15:30 后**启动，允许运行两小时或更久，但必须记录超时、失败和部分成功结果。
- 非交易日仍运行外部信息更新与风险重评；由于没有新的交易日收盘价，非交易日不增加七交易日计数，也不静默改写原始推荐。重大新闻导致结论变化时创建带时间和原因的新修订版本。
- 具体调度时刻和非交易日信息窗口仍需在任务设计时参数化，不能只靠固定自然日定时器判断市场状态。

## 2. 七交易日复盘口径

### 2.1 基准价格与截止价格

- `T0`：推荐分析完成并持久化的时间。
- 基准价格：`T0` 时可获得的最新有效成交价。
- 观察窗口：从 `T0` 后的下一个 A 股交易日开始计数。
- 截止价格：第七个交易日的收盘价。
- 实际涨跌幅：`(第七交易日收盘价 - 基准价格) / 基准价格 × 100%`。
- 如果第七交易日停牌，则先标记“到期但待有效价格”，待复牌后使用首个有效收盘价补充复盘，并同时显示原到期日、实际复盘日和顺延原因。

盘后自动推荐存在一个需要特别处理的边界：如果任务在当日收盘后完成，`T0` 时“最新有效成交价”通常就是当日收盘价；系统仍须保存价格对应的行情时间，不能只保存任务完成时间。

### 2.2 收藏快照

用户收藏推荐时，必须冻结并保留：

- 股票代码、名称和市场；
- 推荐来源（自动推荐或手动分析）；
- 推荐完成时间及数据截止时间；
- 基准价格及对应行情时间；
- 上涨概率估计、预计涨跌幅区间和推荐购买指数；
- 推荐理由、风险提示、模型版本和策略版本；
- 计划复盘日期。

后续重新分析同一股票必须生成新版本，不得覆盖已收藏推荐的原始预测值。

### 2.3 到期复盘结果

第七交易日收盘数据可用后，系统记录：

- 实际涨跌幅；
- 上涨方向是否预测正确；
- 实际涨跌幅是否落入预测区间；
- 实际值超出预测区间时，与最近区间边界的百分点偏差；
- 复盘使用的截止价格、行情时间和数据源；
- 停牌、缺失数据或任务失败状态。

“准确率偏差”不能只显示一个含义不明的百分比。第一版至少应分别展示方向命中、区间命中和区间外偏差。

## 3. 推荐结果统一数据契约

自动推荐和手动分析至少共享以下逻辑字段：

| 字段 | 含义 |
| --- | --- |
| `source_type` | `scheduled` 或 `manual` |
| `stock_code` | A 股标准代码 |
| `completed_at` | 分析完成时间 |
| `data_as_of` | 输入数据截止时间 |
| `baseline_price` | 推荐基准价格 |
| `baseline_market_time` | 基准价格对应的行情时间 |
| `rise_probability_estimate` | 模型估计的七交易日上涨概率 |
| `return_range_low` / `return_range_high` | 预计涨跌幅区间上下界 |
| `purchase_index` | 0～100 推荐购买指数 |
| `rationale` / `risk_notes` | 推荐理由与风险提示 |
| `model_version` / `strategy_version` | 可追溯的模型和策略版本 |
| `review_due_date` | 计划复盘交易日 |
| `status` | 等待、运行中、成功、失败、数据不足或已复盘 |

数据库与界面实现前，应先把上述字段落实为后端模型、迁移和接口契约，再制作运行页面，避免页面先行导致字段反复变化。

## 4. 自动推荐任务边界

建议的首版任务流程如下：

1. 确认当天是 A 股交易日且收盘数据完整；
2. 先用可解释的基础规则从 A 股股票池筛出候选集；
3. 对候选集运行 AI 分析，而不是每天对全市场逐股运行多智能体分析；
4. 按统一推荐指数排序并输出 10～20 只；
5. 保存成功、失败、耗时、模型成本和策略版本；
6. 对不足 10 只的结果如实展示，不得用低质量或失败结果凑数。

10～20 只是目标展示数量，不是必须填满的硬指标。候选条件不满足或上游数据异常时，宁可少于 10 只，也不能降低约束后静默补足。

### 4.1 推荐购买指数 v0.1

第一版采用可解释、可版本化的启发式公式，不把未经回测的权重描述为科学最优。所有子分数范围均为 0～100：

| 子分数 | 初始权重 | 建议计算口径 |
| --- | ---: | --- |
| 上涨概率分 `P` | 30% | 模型估计上涨概率乘以 100；界面继续标注“模型估计、非实际结果” |
| 收益机会分 `R` | 20% | 由预测区间中点决定，并因区间过宽而降低；归一化阈值由滚动历史分位数确定 |
| 波动风险分 `V` | 20% | 结合 20 日实现波动率、ATR、近 60 日最大回撤和预测区间下界；风险越高得分越低 |
| 流动性分 `L` | 10% | 20 日成交额中位数、有效报价率和冲击成本代理指标的横截面分位数 |
| 分析一致性分 `C` | 10% | 多智能体方向一致程度；只有一个模型结论时不得伪造一致性分 |
| 数据质量分 `D` | 10% | 行情、财务、新闻的新鲜度、完整度和来源状态 |

基础指数：

```text
base_index = 0.30P + 0.20R + 0.20V + 0.10L + 0.10C + 0.10D
purchase_index = clamp(round(base_index - penalties), 0, 100)
```

初始风险处罚建议如下，具体数值必须通过历史样本验证后再冻结：

- ST 或 `*ST`：处罚退市、涨跌停和信息风险，但不禁止分析；
- 上市未满 60 个交易日：处罚历史样本不足和波动不稳定风险，但不排除；
- 停牌、行情过期、关键数据缺失：禁止生成正常购买指数，状态改为“数据不足”；
- 预测区间下界明显为负、流动性极差或模型严重分歧：追加处罚；
- 同一风险不能在 `V`、`D` 和 `penalties` 中重复扣分，计算明细必须可追溯。

`R`、`V` 和 `L` 优先使用同一交易日 A 股横截面或固定滚动窗口的分位数归一化，避免把人为常数当作永久市场规律。指数页面需要允许展开查看六项子分数、处罚项、公式版本及数据时间。v0.1 只用于排序和研究，不应映射为“保证买入”结论；积累到期样本后再用方向命中、区间命中、回撤和概率校准结果调整权重。

## 5. 手动搜索与分析边界

手动流程拆分为两个动作：

1. **搜索股票**：本地或行情股票池检索，不调用大模型；
2. **生成分析**：用户选择股票后主动触发 AI 任务。

这样可以避免用户每输入一个字符就触发昂贵且缓慢的多智能体分析。手动分析目标为尽量在 **30 秒内**完成；这是产品性能目标，不是当前已验证能力。首版应采用较小的并行分析流程、严格的数据获取超时和可取消任务，页面显示运行状态、等待提示、取消或重试入口，以及失败原因。若完整多智能体流程无法在 30 秒内完成，应明确提供“快速分析”和“完整分析”，不能返回未完成结果却标记成功。相同股票在短时间内重复分析时，可以提示复用缓存，但必须让用户看到缓存生成时间并允许重新分析。

## 6. 实施前仍需产品负责人确认

以下决定仍会影响数据源、数据库或任务调度，不能在编码时隐式猜测：

1. **退市整理范围**：是否允许搜索和分析退市整理期股票；
2. **盘中刷新指标**：目标刷新间隔，以及可接受的最大行情延迟；
3. **非交易日更新**：哪些外部信息触发重新评估，以及修订结果是否向用户主动通知；
4. **候选池规则**：自动推荐是否对 ST、`*ST`、新股和低流动性股票设置入选上限；这些股票已确认可以分析，但不等于必须进入每日推荐；
5. **推荐指数名称**：继续使用“推荐购买指数”，还是改为风险更低的“AI 关注指数”；
6. **推荐指数公式**：概率、收益区间、波动风险、流动性和多智能体一致性的权重；
7. **收藏删除规则**：取消收藏后是否仍保留原推荐及复盘历史；
8. **AI 预算**：选定模型和分析调用预算；自动任务允许两小时以上，手动分析以 30 秒为目标；
9. **TradingAgents 路径**：直接集成、独立服务部署，或仅参考其多智能体流程重新实现。

## 7. 开发准入条件

在第 6 节至少确认第 1、2、3、5、6、8 项前，不开始完整 AI 推荐功能开发。可以先进行：

- 行情源和 TradingAgents 技术评估；
- 统一数据契约设计；
- SQLite 迁移草案；
- 使用固定测试数据验证推荐、收藏和复盘流程；
- 实时自选现状审计和离线测试补齐。

这一顺序把数据与计算口径先固定，再接入真实行情和模型，可以显著降低页面、数据库和任务调度同时返工的风险。
