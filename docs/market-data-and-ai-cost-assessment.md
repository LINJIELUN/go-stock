# A 股行情数据源与 AI 成本初步评估

> 调研日期：2026-08-10。此处是实施前初筛，不是数据准确性认证，也不是采购建议。仓库活跃度、模型和价格会变化，正式选型必须重新核对官方授权、服务条款、报价和实测 SLA。

## 已确认预算边界（2026-08-12）

- 行情数据预算是**每月不超过 20 美元**，可以注册、购买并接受实名认证。
- 该预算与 AI 模型预算分开核算，不能用 AI 的 50/100 美元软硬预算弥补行情超支。
- “客户端每 5 秒请求一次”仍只是刷新目标，不等于交易所授权的实时行情，也不等于端到端延迟小于 5 秒。
- 在供应商提供书面授权范围、字段清单、延迟说明和限流规则以前，不对外宣称数据为交易所级实时数据。

20 美元约束可以用于低价个人套餐、积分制接口或开发验证，但目前没有证据证明它能同时覆盖沪深北和 ETF、5 秒轮询、主力净流入等衍生字段、稳定 SLA，以及可用于应用展示的授权。特别是“主力净流入”通常是供应商定义的衍生口径，不能假定不同供应商数值可直接互换。

第一阶段采用双层目标：先在预算内验证最新价、涨跌幅、成交量/额、换手率和量比的覆盖率、延迟与限流；主力资金字段如果没有合规且稳定的数据源，页面必须标记“暂不可用”，不能用估算值冒充供应商数据，也不能静默抓取网站页面作为生产方案。

## 1. 先澄清“开源代码”和“准确实时数据”

GitHub 项目通常提供数据访问代码，不拥有交易所实时行情本身。代码开源不代表其上游数据：

- 获得交易所授权；
- 没有延迟；
- 允许在本软件中再展示或分发；
- 具备稳定性、字段兼容性或服务等级承诺。

因此不能通过找到一个“实时行情 GitHub 项目”就认定数据准确。生产数据源应按授权、时间戳、覆盖范围、限流、延迟分布、故障率和主备口径进行验收。

## 2. GitHub 候选项目初筛

| 项目 | 已核实事实 | 适合用途 | 主要限制 |
| --- | --- | --- | --- |
| [AKShare](https://github.com/akfamily/akshare) | MIT 许可的 Python 财经数据接口库，聚合多类上游来源 | 快速验证字段、补充低频基本面和资讯 | 引入 Python 运行栈；聚合接口不等于交易所授权实时源，上游页面变化会影响稳定性 |
| [mootdx](https://github.com/mootdx/mootdx) | MIT 许可，README 明确提供“通达信线上行情读取” | 验证通达信行情协议、服务器与字段 | Python 实现；公开服务器的可用性和授权需另行核实，不能仅凭能连接就作为生产 SLA |
| [pytdx](https://github.com/rainx/pytdx) | 通达信协议 Python 项目；GitHub 仓库已归档 | 仅作为协议历史参考 | 已归档，不建议成为新增生产依赖 |
| [Tushare](https://github.com/waditu/tushare) | Python SDK README 提供实时交易数据示例，项目采用 BSD-3-Clause | 股票基础资料、交易日历、历史和结构化数据候选 | 实时覆盖、积分或套餐、调用额度和展示授权须向官方确认；Python SDK 不应直接等同于数据 SLA |
| [TradingAgents](https://github.com/TauricResearch/TradingAgents) | Apache-2.0，多智能体研究框架，README 声明支持沪深 A 股代码和多家模型供应商 | 参考研究流程、角色分工和可追溯分析 | 不是实时行情供应商；完整多智能体流程的耗时与 Token 成本可能不满足单股 30 秒目标 |

本项目已经有 Go 行情层，并组合东方财富、腾讯、新浪、通达信和 Tushare 等能力。优先策略应是给现有 Go 数据接口增加统一时间戳、质量状态、主备切换和实测指标，而不是为了调用某个 Python 库立即引入第二套运行时。

## 3. 推荐的数据源分层

### 3.1 生产首选

对“尽量实时且准确”的目标，首选具有明确授权、行情时间定义、频率额度和服务承诺的商业行情服务。候选服务必须书面确认覆盖上交所、深交所、北交所、ETF 和 ST，并允许桌面软件展示。具体供应商尚未完成采购级核实，因此本文不虚构排名。

### 3.2 开发与降级源

- 通达信协议能力：作为低成本快照候选和交叉对账源；
- 东方财富、腾讯、新浪等现有接口：用于开发、字段补充或故障降级；
- Tushare：优先考虑交易日历、股票基础数据和历史结构化数据；
- AKShare：用于研究验证和快速比较，不直接作为唯一生产依赖。

开发阶段可以先实现 5 秒轮询目标，但只有实测达到延迟和可用率要求后才能对外写“5 秒刷新”。客户端至少保存并显示：

```text
source
market_time
fetched_at
is_stale
quality_status
fallback_reason
```

## 4. 数据源验收实验

对候选主源和备源连续记录至少 10 个完整 A 股交易日：

1. 固定样本覆盖沪、深、北交所，ETF、ST、新股、停牌及高低流动性股票；
2. 每次采集保存供应商行情时间和本机接收时间；
3. 统计中位数、P95 和 P99 延迟，成功率、空值率、重复快照率和限流次数；
4. 对价格、昨收、涨跌幅、成交量、成交额、换手率和资金流单位逐字段对账；
5. 模拟断网、超时、空响应、字段变化和主源失败；
6. 未通过授权与 SLA 检查的来源只能标记为开发或降级源。

完成实验前，“实时”属于待验收目标；不能把一次请求成功当作持续实时能力。

## 5. AI 成本如何估算

模型费用通常按输入和输出 Token 计费，多智能体框架会让同一股票经历多个角色、工具结果和讨论轮次，因此不能只按“一次聊天”估算。统一公式为：

```text
单股成本 = Σ(每次调用输入 Token × 输入单价 + 输出 Token × 输出单价) / 1,000,000
每日成本 = 自动分析候选股数量 × 单股成本 + 手动分析成本 + 非交易日重评成本
月成本 = Σ每日实际成本
```

必须在每次调用记录供应商、模型、缓存命中、输入 Token、输出 Token、耗时和费用估算，设置每日软预算与硬预算。

## 6. 用量场景，而不是虚构固定报价

以下是用于理解规模的 Token 假设，不是供应商报价：

| 模式 | 每股模型调用 | 假设总输入 | 假设总输出 | 用途 |
| --- | ---: | ---: | ---: | --- |
| 手动快速 | 1～2 次 | 20k～50k | 2k～6k | 目标 30 秒内返回 |
| 自动标准 | 5～8 次 | 80k～200k | 10k～30k | 多角色并行分析与汇总 |
| 自动深度 | 10～20 次 | 200k～600k | 30k～100k | 完整辩论、风险复核和修订 |

如果先量化筛出 40 只候选，再对其运行“自动标准”并最终展示 10～20 只，每个交易日大约消耗 3.2M～8M 输入 Token 和 0.4M～1.2M 输出 Token。月成本需要把这些用量乘以最终模型的官方单价；不同模型价差很大，在选定供应商前给出单一金额会造成虚假精确。

作为当前报价读取示例，[DeepSeek 官方定价页](https://api-docs.deepseek.com/quick_start/pricing/)在调研日列出：V4 Flash 每百万 Token 的缓存未命中输入为 0.14 美元、输出为 0.28 美元；V4 Pro 分别为 0.435 美元和 0.87 美元。按上述每天 40 只“自动标准”、每月 22 个交易日且保守地不计算缓存优惠：

| 示例模型 | 估算每日 | 估算每 22 个交易日 | 未包括 |
| --- | ---: | ---: | --- |
| DeepSeek V4 Flash | 约 0.56～1.46 美元 | 约 12.32～32.03 美元 | 手动分析、非交易日重评、失败重试、汇率和税费 |
| DeepSeek V4 Pro | 约 1.74～4.52 美元 | 约 38.28～99.53 美元 | 同上 |

这是 Token 假设乘以调研日公开单价得到的场景估算，不是账单承诺。实际 TradingAgents 上下文长度、工具结果、重试和缓存命中会显著改变费用；其他供应商也可能高出很多。价格会变化，应在预算确认时从官方页面重新读取，不能把本文数字写死进代码。

## 7. 控制成本与满足 30 秒手动目标

- 手动分析使用单次并行数据获取和 1～2 次模型调用，不直接运行完整 TradingAgents 辩论；
- 自动任务先用非 AI 规则缩小候选池，再让多智能体分析；
- 缓存同一交易日的行情、财务和新闻材料，避免每个智能体重复拉取和重复输入；
- 外部工具返回结构化摘要，不把整篇新闻或整份财报反复送入模型；
- 自动任务可使用成本较低的模型做初筛，只对高潜力或结论冲突的股票调用更强模型；
- 非交易日只重评有新增重大信息的股票，不对全部股票无差别重跑；
- 达到硬预算后停止新任务并告警，不以截断输出伪装成功。

初始模型预算确定为每月 **50 美元软预算、100 美元硬预算**，自动推荐、手动分析、非交易日重评和失败重试均计入同一预算：

- 达到 50 美元时通知用户并展示剩余预算预测，但不自动中止已有任务；
- 达到 100 美元时不再启动新的付费模型任务，已开始的任务允许正常完成并记录可能的少量超额；
- 本地 Ollama 等没有 API Token 账单的模型仍记录 Token 和耗时，但不计入供应商费用；
- 预算周期、币种、供应商账单时区和汇率必须记录，不能把美元阈值直接当作人民币扣费；
- 用户可调整预算，但修改只影响后续任务，不改写历史成本。

建议先实施一周“影子运行”：不向用户正式展示 AI 推荐指数，只记录每股 Token、费用、耗时、失败率和指数分项。得到真实分布后，再判断当前预算是否足够，并校准每天候选数量和模型组合。
